# TinyStories 实验结果汇总

更新于 2026-09-20：已纳入 batch=1、实际 micro-batch 探测与高学习率短跑。完整理论推导、tokenizer / OWT 实验、生成样例及范围说明见根目录 [writeup.md](../writeup.md)。实验产物和实现已合并到自己的 fork 的 `main`。

本文件汇总作业过程中的实测日志。三组新架构结果按执行顺序对应 postnorm、no_rope、silu。验证使用固定抽样的 80 条长度为 256 的序列；不是完整验证集平均。以下为单种随机种子的观测，未估计统计置信区间。

## 完整训练

两组均为 40,000 步、327,680,000 tokens，有效 batch=32，V=10,000、T=256、D=512、L=4、H=16、SwiGLU F=1344。minimum LR 是 peak LR 的 0.1 倍，warmup 为 200 步。

| 峰值 LR | 最终验证 loss | 最佳验证 loss | 最佳步数 |
|---|---:|---:|---:|
| 3e-4 | 1.4644036233 | 1.4626254857 | 39,500 |
| 1e-3 | 1.3987042308 | 1.3965284765 | 38,300 |

lr=1e-3 在当前验证设置下低于 1.45。该运行曾重复启动并终止第二进程；最终审计没有损坏 JSON 行，有 8 条重复记录，latest 与 best 的步数、最佳值与日志一致，最佳 checkpoint 成功用于生成文本。原始日志和恢复前备份应保留；去重绘图不意味着证明中间所有记录不受影响。

## 学习率初筛

共同预算：4,000 步、32,768,000 tokens；40,000 步余弦日程，不把日程压缩到短跑长度。

| 峰值 LR | 验证 loss |
|---|---:|
| 3e-4 | 1.8868142426 |
| 1e-3 | 1.8065583944 |
| 3e-3 | 1.8648310542 |

3e-3 表现较差不等于发散，学习率发散边界尚未取得。

额外的高学习率检查使用 1,000 步、8,192,000 tokens：1e-2、3e-2、1e-1 的最终验证 loss 分别为 3.031969、4.805609、5.541289。后两组分别从短跑最佳 3.712003（step 120）和 4.168119（step 100）回退，存在明显不稳定；记录仍为有限值，不能据此声称已定位严格发散边界。曲线与日志已归档于 `reports/training/lr_1e2`、`lr_3e2`、`lr_1e1`。这三组预算不同于上表，不直接比较端点排名。

## Batch 对照

固定峰值 LR=1e-3；batch=1 使用 micro-batch=1、累积 1 次，其他三组使用 micro-batch=4 并通过梯度累积改变有效 batch。按 token 数缩放完整日程、warmup 与暂停步数。四组共同预算为 32,768,000 tokens。

| 有效 batch | 完成步数 | 验证 loss |
|---|---:|---:|
| 1 | 128,000 | 2.6442774415 |
| 32 | 4,000 | 1.8065583944 |
| 64 | 2,000 | 1.8074839950 |
| 128 | 1,000 | 1.8220951080 |

32 与 64 的差异仅 0.0009256，单次实验不足以宣称统计显著性。128 在该学习率、预算下略差，batch=1 明显较差。但没有为各 batch 分别重新调优学习率；不同 batch 的每 token 更新次数、累计 AdamW weight decay 也不同，不能把差异全部归因于梯度噪声。batch=1 已完成，累计耗时 3,330.351 s，约 55.51 min，曲线已加入对比图。

Micro-batch 容量探测也已经执行：1/2/4/8/16/32/64/128/256 各执行 3 次完整 optimizer 更新，均成功，没有触发 OOM，达到搜索上限 256。最后两项 PyTorch peak allocated 为 10.919 / 21.525 GiB，超过本机约 7.96 GiB 的物理显存；可能涉及 WSL / 驱动的系统内存回退，但未直接测量分页。该记录不能解释为纯物理 VRAM 容量，也不能将 256 当成已找到的最大 batch。详细结果见 [探测摘要](evidence/microbatch_summary.json)。

## 架构消融

共同配置：有效 batch=32、峰值 LR=1e-3、minimum LR=1e-4、warmup=200、完整日程 40,000 步，均从新初始化训练到 4,000 步，即 32,768,000 tokens。

| 架构 | 验证 loss | 相对原模型增量 |
|---|---:|---:|
| 原模型：pre-norm + RoPE + SwiGLU | 1.8065583944 | 0 |
| 无门控 SiLU FFN | 1.8436145425 | +0.0370561481 |
| Post-norm | 1.8562417150 | +0.0496833205 |
| NoPE | 1.9068757415 | +0.1003173470 |
| 无 RMSNorm | 1.9450056493 | +0.1384472549 |

原模型在这次固定配置的短预算实验中最低，不据此推出所有架构在充分训练、各自调参后的最终排名。四种改动的精确定义：

- 无 RMSNorm：移除 block 内及最终的全部 RMSNorm。
- Post-norm：每个子层先执行残差相加，再归一化；保留最终 ln_final，仅考察 block 内归一化位置的变化。
- NoPE：取消 Q/K 的 RoPE 旋转，保留因果 mask；因果 mask 本身仍带有顺序限制，不能理解为完全没有顺序信息。
- SiLU：FFN 为 W2 SiLU(W1 x)，F=2048；共 22,827,520 个参数，原模型 22,696,448，属于近似参数匹配。

无 RMSNorm 的另一组峰值 LR=3e-4 在同预算下验证 loss=1.9610856891；对应有 RMSNorm 的参照为 1.8868142426。降低 LR 未改善此时的无归一化结果，不能写成“降低学习率恢复稳定”。两组都完成 4,000 步，完整验证曲线已归档、已检查，记录点没有出现非有限 loss；这不排除采样间隔内未记录的短暂波动。

新三组累计日志时间分别为 853.3581、937.2451、983.6802 秒。它们与更早运行的吞吐环境不同，不能仅据总时间或最后一个日志窗口将差异归因于架构。所有短跑结论均不代表充分收敛。
